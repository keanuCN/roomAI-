# AI 家装方案在线 Demo 技术方案

- 文档状态：讨论稿
- 日期：2026-10-27
- 目标：基于 Roomsmith 的空间建模和设计流程，规划一个可在线访问、面向家具/建材商家及装修设计团队的可视化 Demo。
- 当前约束：本阶段只验证核心体验，不建设完整企业 SaaS；使用云端模型；运行和设计流程不依赖 Claude Code。

## 1. 产品目标

Demo 让潜在 B 端客户直观看到：上传房间资料、编辑户型、选择产品、生成设计效果，并把带产品信息的方案分享给消费者。

首版支持两类业务：

1. 家具/建材品牌或门店：将自有产品放入房间方案，展示产品属性、搭配效果和询价入口。
2. 装修公司/室内设计工作室：根据客户需求和房间尺寸制作多个设计方向，展示布局、材料和预算说明。

首版使用一个预置的示例企业、品牌样式和产品目录。租户管理、员工权限、企业自助配置等功能保留为后续扩展。

## 2. 设计原则

- 空间几何可核验：房间尺寸、墙体、门窗、家具占位由结构化数据和程序计算；图像模型用于视觉呈现，不负责决定尺寸。
- 先确认再生成：效果图生成前显示预计调用量和费用；单项目、单用户均有上限。
- 方案可解释：保存设计方向、产品引用、改动理由、预算和版本。
- 面向企业展示：项目结果可生成带品牌信息的客户分享页。
- 可演进为多租户：产品、项目和分享数据模型预留企业标识与访问控制字段。
- 模型供应商可替换：调用封装在 Provider 接口中，密钥只存在服务端。

## 3. Demo 范围

### 3.1 首版包含

- 上传房间照片，填写房间用途、风格、预算和保留物品。
- 通过 2D 编辑器创建或修正房间轮廓、墙长、门窗位置；支持矩形房间和简单凹角房间。
- 查看平面图、尺寸、门窗和家具位置；编辑器以结构化坐标保存。
- 浏览预置家具/建材目录，选择产品加入设计方案。
- 生成 2 至 3 个设计方向；选择方向后生成效果图。
- 展示方案理由、产品清单、预估价格和免责声明。
- 生成只读客户分享页，包含示例企业品牌、方案、产品和询价/联系入口。
- 提供项目保存、方案版本、删除项目和分享链接失效功能。
- 提供演示模式：可使用预生成图片，不调用模型；真实生成由用户明确触发。

### 3.2 首版暂缓

- 企业注册、企业工作区、员工邀请与精细角色权限。
- 多企业自助配置品牌和商品目录。
- 支付、订阅、发票、库存与 ERP/PIM/CRM 集成。
- 实时多人协同编辑和评论通知。
- 自动从照片推算精确尺寸、施工图、CAD/BIM 导出。
- 移动端原生应用和复杂 3D 拖拽编辑器。

## 4. 用户流程

1. 用户进入 Demo，可选择“体验示例”或“新建方案”。
2. 新建时上传照片并填写房间基本信息；系统提示尺寸需人工确认。
3. 用户在 2D 编辑器中确认房间尺寸、墙体和门窗，保存房间模型。
4. 用户选择产品目录中的家具/材料，或暂时跳过产品选择。
5. 系统根据房间模型、用户偏好和产品信息生成设计方向及文字说明。
6. 用户确认生成预算后，异步生成效果图并显示任务状态。
7. 用户比较方案、调整产品、保存版本并生成客户分享链接。
8. 客户打开只读分享页，可查看效果、产品细节并提交询价/预约信息。

## 5. 系统架构建议

### 前端

- Next.js + TypeScript，提供响应式网页、项目编辑器和分享页。
- 2D 平面编辑器优先使用 SVG 坐标层；尺寸标注、吸附、选中和拖拽由前端处理。
- 编辑器所有几何操作同步到结构化 Room JSON；图片仅作为参考背景。
- 编辑器状态与服务端保存版本分离，支持撤销/重做和自动保存。

### 后端

- Python FastAPI，复用或提取 Roomsmith 的房间模型、几何校验、平面图绘制和报告生成逻辑。
- 设计流程以显式状态机实现：Brief → Room Model → Directions → Render Approval → Render → Share/Report。
- 不调用 Claude Code，不依赖终端 Agent。后端直接调用模型 API 和内部几何模块。
- 长时间图像生成使用异步任务；首选托管队列或 Redis 队列，页面轮询任务状态。需要实时进度时再增加 SSE/WebSocket。

### 数据和文件

- PostgreSQL：项目、房间、产品、方案版本、生成任务和询价线索。
- S3 兼容对象存储：原始照片、生成图片、PDF；数据库只保存对象键和元数据。
- 分享 URL 使用高熵随机令牌，不暴露数据库自增 ID；支持过期、撤销和只读访问。
- Demo 数据使用单一示例企业记录；后续正式多租户时，所有企业数据表增加 tenant_id 并在服务层强制校验。

### 云端模型

- 文本/视觉模型：提取需求、总结照片内容、生成方案描述和产品搭配建议。
- 图像模型：基于原始空间照片、房间模型渲染图和产品参考图生成视觉效果。
- Provider Adapter：统一配置模型名称、超时、重试、成本估算和错误处理。
- API 密钥仅保存在服务端密钥管理/环境配置中，不下发到浏览器。
- 生成任务保存 provider、model、prompt 版本、输入文件引用、费用估算、实际用量和状态。
- 输出图片只作设计展示；不得将图片当作精确的尺寸或施工依据。

## 6. 核心数据对象

| 对象 | 主要字段 | 说明 |
|---|---|---|
| DemoBrand | id, name, logo, theme, contact | 首版示例企业品牌 |
| Product | id, brand_id, name, category, dimensions, materials, price, images | 家具/建材产品；价格允许标为示例价 |
| Project | id, brand_id, title, status, created_at, updated_at | 一次客户设计项目 |
| Room | id, project_id, geometry_json, openings_json, confirmed | 房间结构和尺寸；confirmed 表示用户确认 |
| DesignVersion | id, project_id, room_id, direction, product_ids, rationale, budget | 一个设计方向及其产品引用 |
| RenderJob | id, design_version_id, provider, model, status, estimated_cost, actual_cost | 异步模型调用任务 |
| ShareLink | id, project_id, token_hash, expires_at, revoked_at | 客户只读分享授权 |
| Lead | id, project_id, share_link_id, contact, message, consent_at | 客户提交的询价/预约信息 |

几何 JSON 使用统一坐标单位（厘米或毫米，需在实现前定稿），保存房间多边形、墙段、开口和家具包围盒。绘制用 SVG，计算和导出使用同一份几何数据。

## 7. 主要 API 草案

| 方法与路径 | 用途 |
|---|---|
| POST /api/projects | 创建项目 |
| GET /api/projects/{id} | 读取项目和当前状态 |
| PUT /api/projects/{id}/room | 保存房间几何和尺寸 |
| GET /api/products | 查询 Demo 产品目录 |
| POST /api/projects/{id}/directions | 根据需求和产品生成方案文字/方向 |
| POST /api/design-versions/{id}/renders | 确认预算并创建图像任务 |
| GET /api/render-jobs/{id} | 查询生成状态、图片和费用 |
| POST /api/projects/{id}/share-links | 创建只读分享链接 |
| GET /share/{token} | 读取客户展示页内容 |
| POST /share/{token}/leads | 提交询价/预约信息 |

所有项目读写接口必须校验项目访问令牌/会话。分享接口仅返回展示所需字段，不返回内部提示词、API 信息或私有文件地址。

## 8. 费用、隐私与滥用控制

- 每次生成前展示图片数量、预计费用和是否会使用真实模型。
- 设置每日匿名体验次数、单项目费用上限、上传文件大小/格式限制和并发限制。
- 对模型调用做超时、有限重试和幂等控制，避免重复扣费。
- 上传文件使用私有对象存储；分享页通过短时签名 URL 读取必要图片。
- 提供删除项目入口；Demo 设置明确的文件保留周期，并在到期后清理原图和生成物。
- 询价表单告知用户数据用途并记录同意时间；生产上线前再确定隐私政策、数据区域和合规要求。
- 公开分享链接可设置过期时间和撤销；链接访问记录只保存必要的安全/统计信息。

## 9. Docker 容器化方案

### 9.1 本地开发与 Demo 环境

使用 Docker Compose 一键启动依赖服务，避免开发者分别安装数据库、队列和对象存储。建议服务如下：

| 服务 | 容器职责 | 本地端口建议 |
|---|---|---|
| web | Next.js 网页、户型编辑器和客户展示页 | 3000 |
| api | FastAPI、项目/产品 API、几何校验、模型任务创建 | 8000 |
| worker | 执行文本/视觉模型请求、图像生成、PDF 任务 | 不直接暴露端口 |
| postgres | 项目、房间、产品、任务和询价数据 | 5432，仅开发环境映射 |
| redis | 异步任务队列和短期任务状态 | 6379，仅开发环境映射 |
| minio | 本地 S3 兼容对象存储，保存上传照片和生成物 | 9000；管理界面 9001 |

建议仓库包含根目录 compose.yaml、前端 Dockerfile、后端/Worker Dockerfile 和 .env.example。api 与 worker 可复用同一后端镜像，通过不同启动命令运行；web 独立构建。Compose 负责服务依赖、健康检查、网络和本地数据卷。

### 9.2 本地运行约定

- 使用命名卷保存 PostgreSQL 与 MinIO 数据；删除容器时不自动清除用户测试数据。
- Redis 可作为可重建队列；任务的最终状态仍写入 PostgreSQL，Worker 重启后可恢复或标记中断任务。
- 只把需要浏览器访问的 web 端口暴露到主机。数据库、Redis 和对象存储管理端口仅用于本机开发，不直接暴露到公网。
- 模型 API 密钥放在未纳入版本控制的 .env 文件中；.env.example 只列变量名和占位说明。
- 前端仅访问 api；模型供应商密钥、数据库凭证和对象存储密钥不得进入前端环境变量或静态资源。
- 图像生成由 worker 调用云端模型。容器不下载模型权重，也不要求 GPU。

### 9.3 线上部署

- web、api、worker 构建为独立、带版本号的 Docker 镜像；演示和生产使用同一镜像，通过环境配置区分。
- 小规模 Demo 可部署在单台云主机的 Compose 环境；公网流量经 HTTPS 反向代理进入 web/api。
- 面向真实 B 端客户后，优先使用托管 PostgreSQL、托管 Redis/队列和云端对象存储；不把生产数据库和客户文件只放在单机容器卷中。
- 生产模型密钥使用云厂商密钥管理或部署平台 Secret 注入，不提交到 Git、不写入镜像层。
- 数据库迁移作为独立部署步骤运行，不让多个 API 副本同时自动改表。
- 为 web/api/worker 设置健康检查、资源限制、日志轮转和重启策略；监控队列积压、模型错误、生成耗时与费用。
- 开发、演示、生产使用隔离的数据库、存储桶、密钥和模型额度。

### 9.4 建议交付文件

| 文件 | 用途 |
|---|---|
| compose.yaml | 本地启动 web、api、worker、postgres、redis 和 minio |
| compose.prod.yaml | 线上容器编排覆盖项；连接托管数据库、队列和对象存储 |
| web/Dockerfile | 构建 Next.js 前端镜像 |
| backend/Dockerfile | 构建 FastAPI 与 Worker 共用镜像 |
| .env.example | 环境变量清单和无效占位值 |
| .dockerignore | 排除本地缓存、密钥、上传文件和构建产物 |

以上是文档中的目标交付结构，当前阶段只记录方案，尚未创建 Docker 配置文件。
## 10. 部署形态建议

- 前端部署在支持 Next.js 的托管平台；后端部署为容器化 FastAPI 服务。
- 数据库使用托管 PostgreSQL；图片使用独立对象存储；生成任务队列可独立扩容。
- 开发、演示和生产环境隔离；各环境使用独立模型密钥、数据库和存储桶。
- 监控接口错误率、模型耗时、任务失败率、每项目/每模型成本和存储用量。
- 具体云厂商、部署区域和对象存储服务待产品定位与预算确定后选择。

## 11. 验收标准

- 新用户无需安装 Claude Code，可通过浏览器完成 Demo 流程。
- 用户可创建房间、编辑墙体/门窗并保存；重新打开后尺寸和坐标一致。
- 尺寸校验在图像生成前运行，明显超出房间边界的家具不可静默通过。
- 真实模型调用前显示预算并要求确认；失败任务可重试且不会无限重复计费。
- 客户分享页只读、可撤销、可过期，并展示品牌、方案和所选产品。
- 其他用户不能通过猜测项目 ID 访问项目照片或方案。
- Demo 模式可用预生成素材完整演示主流程，不产生模型费用。

## 12. 实施阶段建议

1. 交互原型：确认项目首页、房间编辑器、方案比较页和客户展示页。
2. Demo 核心：2D 几何编辑、产品样例、预生成效果、分享页和 PDF。
3. 云端模型：模型适配层、异步任务、预算确认、成本记录和限流。
4. 小范围试用：收集家具/建材商家与设计团队的流程反馈，决定产品目录和报价能力优先级。
5. B2B SaaS：企业注册、成员权限、品牌配置、企业商品目录、套餐计费和审计记录。

## 13. 待确认决策

- Demo 首批目标客户：家具/建材门店、品牌方、装修公司、设计工作室，或各选一家试用。
- 设计图采用真实云端生成、预生成演示，还是两种模式并存。
- 房间尺寸单位采用厘米还是毫米。
- 产品价格是示例价、企业手动维护价，还是首版不展示价格。
- 分享链接默认公开、密码保护，还是仅限指定邮箱访问。
- 图片/项目数据保留周期及首发服务区域。
- 实时多人编辑、企业员工权限和在线支付的优先级。
